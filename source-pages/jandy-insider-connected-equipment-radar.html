Field rule

For connected equipment, the first question is no longer just "what part failed?" It is "which layer failed: local controller, app/cloud, network, schedule, sensor, relay, RS-485, or the actual equipment?"

Reference only. Verify current manuals, model numbers, wiring, code, safety steps, and qualified-service boundaries before ordering or changing equipment.

1. Local-first automation proof

AquaLink EDGE points to local intelligence at the pool pad, with cloud services supporting remote visibility rather than being the only control path.

  • Capture local in-can display status.
  • Capture Home Hub or local screen state.
  • Capture app/cloud screen with timestamp.
  • Record primary Wi-Fi, backup network, or hotspot state.
  • Photograph connected device assignments, relay labels, and RS-485 wiring before changes.

2. Home Hub and user access

Home Hub style controls add profiles, scenes, access levels, smart-home integrations, and local control. That creates new support questions around permissions and expectations.

  • Ask what profile, scene, or access level was used.
  • Separate "guest cannot change it" from equipment failure.
  • Document Alexa, Google Home, Apple Home, and app route only as control context.

3. Smart heater evidence

JXiQ style heater language reinforces sensor-informed heating, gas pressure, flow, heat-up estimates, and app-level status.

  • Capture heater model plate and fuel type.
  • Record app alert, local display, setpoint, actual water temperature, flow, and gas-pressure clue if shown.
  • Do not turn sensor language into a repair guarantee.

4. Connected water care

TruClear XL, AOP, and TruSense signals belong in SplashLens as manual-test-first prompts, not autonomous chemistry claims.

  • Capture controller display, cell/window proof, salt reading, manual pH/ORP/sanitizer readings, and flow status.
  • Keep AOP and ozone language supplemental unless current manufacturer and code guidance says otherwise.

5. Smart lighting proof

Infinite WaterColors and AquaLink/iAquaLink lighting create proof needs around controller mode, zones, dimming, transformer load, fixture family, and app color state.

  • Capture fixture family, transformer, controller, automation circuit, zone/grouping, and color/show state.
  • Separate sync/programming issues from failed fixture calls.

6. Pump decision prompts

Variable-speed and SpeedSet content supports SplashLens' pump decision workflow: compare exact repair/replacement facts instead of making blanket replacement claims.

  • Capture motor plate, pump wet-end, THP, voltage, speed type, schedule, flow needs, filter pressure, and utility-rate inputs if using savings math.
  • Never invent savings or compliance pressure.

Should this become a news feed?

Yes, but only as a field-radar feed. The SEO value comes from original SplashLens guidance tied to a source-backed checklist, not from reposting industry news. Good format: one short update, one proof checklist, one app CTA, one source link, one conservative boundary.

App behavior to keep training

  1. Ask for local panel proof before app/cloud conclusions.
  2. Ask for timestamped app state and network state.
  3. Show "source-backed" when the clue comes from official/public source review.
  4. Show "AI-only" when a scan lacks model/label/source proof.
  5. Send a vendor packet only after the second proof photo or missing-proof note is captured.
